# 0.2.0 worklog — WebGPU HDR page

Task (TODO.txt): separate WebGPU f16 canvas page; cross links at the top of both menus and on
the empty screen when WebGPU is missing; exposure / black / white sliders on a histogram so
the page works as an SDR → HDR range expander; detect already-HDR images and give them a
separate control, falling back to `<img>` where reading them on the GPU is not possible.

## Decisions

- **HDR images go to `<img>`, not the canvas.** `createImageBitmap` /
  `copyExternalImageToTexture` hand over the SDR rendition (PQ/HLG tone-mapped, gain map
  dropped), so there is nothing HDR to adjust on the GPU. Their control is CSS
  `dynamic-range-limit` on the `<img>`, a real HDR adjustment that never touches pixels.
- **Detection by header bytes** (`js/sniff.js`), before choosing the path: PNG `cICP`,
  AVIF/HEIF `colr nclx` / `tmap` / Apple `auxC`, JPEG gain-map XMP/URN in the primary
  image's APP segments.
- **Shared `Viewer`, new hooks.** `present(img, item, finish)` keeps the load busy through the
  sniff + upload, so the no-queue navigation rules hold unchanged; `finish` returns `false`
  for a superseded load so the stage does not swap in a stale frame. `blank()` for failure
  and empty. `app.js` is reused as is.
- **Encoded values end to end.** WebGPU canvases take sRGB-encoded values (extended past 1.0);
  the shader decodes only for the expansion math.
- **Expansion curve** `lin * (1 + (peak-1) * Y^2) * gain`: mid-tones stay near SDR, input
  white → peak. Added a **highlights** slider (peak, EV) next to exposure/black/white, since
  levels alone can only clip at 1.0 and exposure alone brightens everything.
- **Mipmaps**, `display-p3` upload and canvas, alpha blended onto the page background.
- `visibility: hidden` for the inactive layer, so the canvas never resizes to 0×0.

## Steps and validation

1. `js/viewer.js`: `present` / `blank` hooks. `test-viewer.js` +13 checks (busy through
   present, stale finish returns false, stage failure reported and blanked, decode failure
   and empty set blank).
2. `js/sniff.js` + `experiments/test-sniff.js`, 32 checks on hand-built headers, incl. a
   64-bit `mdat` before `meta`, bogus box sizes, truncation, text in a COM segment and after
   SOS not counting.
3. `js/gpu.js`, `js/expand.js`, `gpu.html`, `css/gpu.css`; menu link row in both pages.
4. `experiments/test-gpu-browser.js` in headless Chromium 153 (`@sparticuz/chromium`, the only
   browser reachable offline via npm) with SwiftShader WebGPU. First run: every canvas
   presentation destroyed the device — an environment problem, fixed with
   `--use-vulkan=swiftshader`. Second: readback of the canvas after the frame read zeros —
   the current texture expires once presented; the probe now copies it right after the
   submit. Third: 31/31, including f16 readback of white at 1.572 encoded (= 2.83× SDR at
   +1.5 EV), which proves the extended range reaches the canvas.
5. Screenshot check of the panel: level thumbs sit over the histogram's 0 and 1.
