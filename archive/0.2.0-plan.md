# 0.2.0 — WebGPU HDR page: SDR → HDR range expander

## Goal

A second page, `gpu.html`, that shows images on a WebGPU canvas in `rgba16float` with extended
tone mapping, so SDR images can be expanded into the display's HDR headroom. Images that are
already HDR are left alone and shown by the browser, with their own control. `index.html`
stays the plain `<img>` viewer. Both pages share file handling, navigation and the menu.

## Pages and links

- `index.html` — `<img>` viewer, unchanged behaviour.
- `gpu.html` — WebGPU viewer with the adjustment panel.
- The top row of each page's menu names the current page and links to the other one.
- On `gpu.html`, when WebGPU is not available, the empty screen shows a notice and a link to
  `index.html`. The page still works: every image then takes the `<img>` path.

## Display path per image

`Viewer` (shared) decodes each image into a hidden `<img id="pic">`. On `gpu.html` a
`Viewer.present(img, item, finish)` hook runs between decode and report. The load stays busy,
so navigation input is dropped exactly as during decode:

1. `Sniff.file(item.file)` reads the first 512 KB and classifies the file.
2. HDR (`pq`, `hlg`, `gainmap`) or no WebGPU → `#native` `<img>` gets the same blob URL,
   waits for `decode()`, then swaps in.
3. SDR → `createImageBitmap` (resized to the device's `maxTextureDimension2D` if larger),
   histogram sample, upload into an `rgba16float` texture with mipmaps, draw, swap in. A GPU
   refusal (validation or out-of-memory error scope) or a bitmap failure falls back to step 2.

`finish(bad)` returns `false` once the load was superseded, and the stage then does not swap
its output in. `Viewer.blank()` hides the stage on decode failure and when the set empties.
Only one of canvas texture / `#native` holds an image at a time.

Why HDR images are not put on the canvas: the upload path (`createImageBitmap`,
`copyExternalImageToTexture`) delivers the SDR rendition — PQ/HLG tone-mapped, gain map
dropped. Only the browser's own `<img>` compositing keeps their range.

## HDR detection (`js/sniff.js`)

| format | signal |
| --- | --- |
| PNG | `cICP` before `IDAT`, transfer 16 (PQ) / 18 (HLG) |
| AVIF / HEIF | `colr` `nclx` transfer 16/18; `tmap` brand or `tmap` item (ISO 21496-1); `auxC` `…hdrgainmap` (Apple) |
| JPEG | APP1/APP2 of the primary image: Ultra HDR `hdrgm` XMP, ISO 21496-1 URN, Apple `HDRGainMap` XMP |

The ISOBMFF walk descends only `meta`, `iinf`, `iprp`, `ipco` and jumps other boxes by size
(64-bit sizes included). JPEG XL is not parsed (bit-packed codestream header) and is treated
as SDR.

## Canvas and shader (`js/gpu.js`)

- Canvas: `format: 'rgba16float'`, `colorSpace: 'display-p3'`, `toneMapping: { mode:
  'extended' }`, opaque. Upload with `colorSpace: 'display-p3'`, so P3 sources keep their gamut.
- Values are sRGB-encoded end to end — that is what an `srgb`/`display-p3` canvas expects;
  there is no linear canvas colour space. The shader decodes to linear only for the expansion
  and re-encodes with the sRGB curve continued past 1.0.
- Expansion from encoded input `e`:

  ```
  t   = clamp((e - black) / (white - black))
  lin = srgbToLinear(t)
  out = lin * (1 + (2^highlights - 1) * Y(lin)^2) * 2^exposure      Y = P3 luminance
  ```

  The luminance-squared term keeps shadows and mid-tones near SDR and lifts highlights; input
  white lands at `2^highlights` × SDR white. Scaling by a luminance ratio keeps hue.
- Contain fit in the vertex shader (4-vertex strip), same fit as `object-fit: contain`.
- Mipmaps generated by a blit pass per level, trilinear sampling, so large photos minify
  without aliasing.
- Transparent pixels blend onto the page background in the shader.
- Draws on demand: once per upload and at most once per animation frame for slider input.
  Canvas backing size follows `devicePixelContentBoxSize`.
- `Gpu.curve(e, params)` is the JS mirror of the shader, used for the curve plot and tests.

## Panel (`gpu.html` menu)

Between the menu header and the file list:

- status line: WebGPU / extended range support / `(dynamic-range: high)`,
- current image line: `SDR, expanded on the GPU` / `HDR (PQ|HLG|gain map), native <img>`,
- **SDR → HDR** group (active for SDR images):
  - expander on/off (`E`) for before/after,
  - histogram of the image's luma (encoded Rec.709 weights, 256×256 resample, sqrt scale,
    end bins excluded from scaling), clipped zones shaded, output curve overlaid with a dashed
    SDR-white line and a `white → N× SDR` label,
  - **black** and **white** point sliders directly under the histogram, aligned with its axis
    (histogram inset by half a thumb), never closer than 0.02,
  - **exposure** −3…+3 EV, **highlights** 0…+4 EV (default +1.5),
  - **Auto levels** (0.05 % clip each end from the histogram), **Reset**.
- **HDR image** group (active for HDR images): **headroom** 0…100 %, applied to `#native` as
  CSS `dynamic-range-limit` (`standard`, `dynamic-range-limit-mix(standard a%, no-limit b%)`,
  `no-limit`). A note says so when the browser ignores the property.

Settings are global (not per image) and persist in `localStorage`, read on startup and written
1 s after the last change, so a slider drag costs one write; a pending write is flushed when the
page is hidden or closed. Double-click on a slider resets it. Sliders blur on pointer-up so arrow
keys go back to paging images.
