# 0.1.0 — minimal image viewer

## Goal

Open images from disk, page through them full-window with the aspect ratio and HDR range intact.
File API only, no server, no build.

## Interface

Sources, all adding new images into the open list while skipping duplicates already present:

- **Open Files** — `<input type=file accept=image/* multiple>`
- **Open Folder** — `<input type=file webkitdirectory directory multiple>`, recursive
- **Drop** — anywhere on the page, files and/or folders, recursive

Keys:

| key | action |
| --- | --- |
| `←` / `A` / `PageUp` / `Backspace` | previous |
| `→` / `D` / `PageDown` / `Space` | next |
| `Shift`+`Space` | previous |
| `Home` / `End` | first / last |
| wheel down / up | next / previous |
| `F` | open / close the file menu |
| `C` | copy the path of the image on screen |
| `Esc` | close the file menu |

Navigation wraps at both ends.

## Info in the title

Name, position in the set and pixel size live in the window title, not in an overlay. The
title is always on screen, so nothing has to be drawn over the picture, and the page carries
no chrome. Only a file the browser cannot decode is written on the stage, because that is a
condition the user has to act on.

## The side menu

The menu is a full-height left drawer with no screen-tinting overlay on the stage:

- the pointer reaching within 28 px of the left window edge pulls it out,
- the pointer moving past 330 px after entering the menu pushes it back,
- pressing outside the menu closes it immediately,
- a press held for 450 ms on the stage toggles it,
- `F` toggles it, `Esc` and the header `X` button close it.

The header carries **Open Files**, **Open Folder**, **Forget** (clear all), and **X** (close),
followed by the open file count.

Rows are built when the panel opens and when the set changes, never per keystroke. Each row
splits into folder and name (the folder shrinks with `text-overflow: ellipsis` so deep paths
never truncate the file name) followed by two action buttons:

- **Path** — copies that row's relative path to the clipboard,
- **X** — forgets that single file, revoking its object URL if active.

**Forget** (both single-file and all-files) is a memory operation: revoking the live object URL,
dropping `File` references from the list, and when empty detaching `<img src>` and returning
to the empty state.

## Behaviour decisions

- **Order is natural, not lexicographic.** `img2` before `img10`, compared over the whole
  relative path so nested folders group together. Digits compare by value, not by digit count.
- **Deduplicated incremental add.** Opening or dropping files that are already in the list
  does not add duplicates; if all dropped items are already open, the viewer jumps to the
  first matching item.
- **Extension test, not MIME.** OSes and browsers report empty or odd `type` for several
  formats; the extension is the dependable filter.
- **Cross-browser `file://` drag & drop.** Synchronously during the `drop` event (before the
  browser clears `dataTransfer` on handler return), the viewer captures:
  1. `item.getAsFileSystemHandle()` promises (works for folders and files on `file://` in
     Chrome on Windows, where legacy `webkitGetAsEntry` fails with `EncodingError`),
  2. `item.webkitGetAsEntry()` entries (works for folders and files in Firefox),
  3. `dataTransfer.files` / `item.getAsFile()` flat `File` objects as synchronous fallback.
  Dot-directories are skipped and `readEntries` is drained across 100-entry batches.
- **One object URL at a time.** Only the current image holds a blob URL; the previous one is
  revoked on switch.
- **An `<img>`, not a canvas.** A 2D canvas clamps HDR content to 8-bit SDR. An `<img>` is
  composited by the browser with native colour management and HDR tone mapping, and
  `object-fit: contain` provides the whole-page aspect-preserving fit.
- **Wait for pixel decode + 100 ms post-load debounce.** Navigation input is ignored while an
  image is loading and decoding (`img.onload` followed by `img.decode()`), and for 100 ms
  after decode completion. Wheel deltas are discarded while busy or inside the cooldown window
  so queued or inertial events never advance past the newly opened image.

## Structure

```
index.html      markup and script order
css/app.css     dark stage, empty state, side drawer menu, row buttons, drop border
js/files.js     collection: pickers, handle/entry/flat drop walk, filter, natural order
js/viewer.js    <img> lifecycle: load, decode guard, deduplication, per-file removal, URL ownership
js/app.js       wiring: pickers, drop target, key map, wheel, post-load debounce, drawer, title
experiments/    node harnesses, not loaded by the page
```

## Verification

`node experiments/test-*.js` — 219 checks, no browser required:

- `test-files.js` — extension table, natural order, `getAsFileSystemHandle` directory walk,
  `webkitGetAsEntry` batching past 100 entries, hidden-directory skip, synchronous fallback
  when `webkitGetAsEntry` fails with `EncodingError` on `file://` and `dataTransfer.files` is
  cleared after `drop`
- `test-viewer.js` — load lifecycle, `img.decode()` busy hold, wrap at both ends, steps dropped
  while loading, supersede by a new set, deduplicated `addImages`, per-file `remove`, decode
  failure and recovery, object URL lifetime, teardown
- `test-app.js` — full key map, 100 ms post-load debounce on keys and wheel (including slow
  decode with queued events), modifier and focus guards, picker and drop wiring, duplicate-add
  prevention, menu header buttons and per-row `Path` / `X` buttons, drawer open/close gestures
