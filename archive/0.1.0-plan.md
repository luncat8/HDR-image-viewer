# 0.1.0 — minimal image viewer

## Goal

Open images from disk, page through them full-window with the aspect ratio intact.
File API only, no server, no build.

## Interface

Sources, all equivalent, all replacing the current set:

- **Open files** — `<input type=file accept=image/* multiple>`
- **Open folder** — `<input type=file webkitdirectory multiple>`, recursive
- **Drop** — anywhere on the page, files and/or folders, recursive

Keys:

| key | action |
| --- | --- |
| `←` / `A` / `PageUp` / `Backspace` | previous |
| `→` / `D` / `PageDown` / `Space` | next |
| `Shift`+`Space` | previous |
| `Home` / `End` | first / last |
| wheel down / up | next / previous |

Navigation wraps at both ends.

## The open list

A toggle opens a panel listing every file in the current set, in display order, with the
current one marked and scrolled into view. Clicking a row jumps to that file. The header
carries the count and a **Forget** button.

**Forget** is a memory operation, not a navigation one. The object URL holds the blob alive
and every `File` in the list holds a handle to its bytes, so a folder of large images stays
resident even though only the current one is decoded. Forget revokes the URL, drops every
`File` reference, detaches the `<img>`, empties the list and returns to the empty state.

## Behaviour decisions

- **Order is natural, not lexicographic.** `img2` before `img10`, compared over the whole
  relative path so nested folders group together. Digits compare by value, not by digit count.
- **Extension test, not MIME.** OSes and browsers report empty or odd `type` for several
  formats; the extension is the only dependable filter.
- **Folders are walked, not read flat.** Dropped trees go through `webkitGetAsEntry` so a
  whole directory works. `readEntries` yields 100 entries per call and ends with an empty
  batch, so it is drained in a loop. Dot-directories are skipped.
- **Entries are captured during the drag, not at drop.** Chrome invalidates the
  `DataTransferItem` list once `drop` fires, so `webkitGetAsEntry()` returns `null` there.
  A dropped folder therefore has to be captured on `dragenter` and walked at drop time; read
  at drop time it looks like an empty transfer and reports "no images found".
- **One object URL at a time.** Only the current image is decoded; the URL of the previous
  one is revoked on the way out. A 5000-image folder costs one live blob, not 5000.
- **The list is built on demand, never per keystroke.** Opening the panel and changing the
  set rebuild the rows; navigation only moves a class and scrolls the current row into view.
  One delegated click listener on the list, so a large folder costs no per-row closures.
- **A wheel notch, not a wheel event.** A trackpad flick emits dozens of small deltas and
  would otherwise blow through a whole folder in one gesture, so deltas accumulate to a
  threshold of 40 and then a 120 ms cooldown follows each step. The dominant axis wins, so
  horizontal trackpad swipes work. `ctrl`+wheel is left to the browser, and the wheel is not
  claimed at all while the pointer is over the list panel, which scrolls instead.
- **An `<img>`, not a canvas.** A 2D canvas is 8 bits per channel, so an HDR frame drawn into
  one is clamped to SDR on the way out; a `display-p3` context widens the gamut but adds no
  bits. A 16-bit float surface would mean WebGPU. An `<img>` is composited by the browser,
  which decodes, colour-manages and tone-maps the file for whatever the display can do, so
  it is both the correct pipeline and the smaller one. `object-fit: contain` is the same
  aspect-preserving whole-page fit, expressed in CSS instead of in draw calls.
- **A superseded load is dropped.** Each request carries a token; a load that resolves after
  a faster jump neither paints nor updates the HUD.
- **The previous frame stays up** until the next image has decoded, so paging never flashes.
- **Undecodable files are not skipped silently.** The name is reported and the HUD goes red,
  so a missing codec is visible instead of looking like a viewer bug.
- **A set with one image leaves the keys alone.** `preventDefault` is only claimed when there
  is somewhere to move, so space, arrows and the wheel still scroll as usual.

## Structure

```
index.html      markup and script order
css/app.css     dark stage, HUD, empty state, list panel, drop highlight
js/files.js     collection: pickers, drop walk, filter, natural order
js/viewer.js    <img> lifecycle: load, decode guard, object URL ownership
js/app.js       wiring: pickers, drop target, key map, wheel, list, HUD
experiments/    node harnesses, not loaded by the page
```

Classic `<script>` tags in dependency order, each file a global with a `module.exports`
guard, so `file://` works and the same files run under node.

## Verification

`node experiments/test-*.js` — 158 checks, no browser required. Each file is driven against a
stub DOM/`Image`/`URL`/entry tree:

- `test-files.js` — extension table, natural order, `readEntries` batching past 100 entries,
  hidden-directory skip, non-image skip, entry capture across the drop boundary
- `test-viewer.js` — load lifecycle, wrap at both ends, single-image no-op, stale-load
  rejection, decode failure and recovery, object URL lifetime, teardown
- `test-app.js` — full key map with scroll-hijack reporting, modifier and focus guards,
  picker and folder-picker wiring, drop handling including the spent-transfer case, list
  build/navigate/rebuild, forget, wheel threshold, cooldown, axis choice and guards
